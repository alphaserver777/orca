# Orca на dev1-robots

Код настройки Orca 1.4.274 и Codex 0.172.0. Действующая эксплуатационная документация: https://books-demo-176-9-11-143.sslip.io/books/infrastruktura-servisy/page/harness-rabocaia-sreda-komandy-agentov

Программа находится в `/opt/orca`, рабочая среда — в `/opt/professorit`. Профиль Codex сохраняет путь `/home/node` для совместимости истории. Старый `/root/professor_ot` — ссылка на новое расположение. Служба: `professorit-orca-native.service`, адрес на компьютере: http://localhost:3040/ через SSH.

## Сценарии

- `migrate-from-pilot.py` — исходный однократный перенос пробной установки из Docker с закрытой резервной копией; повторная перезапись данных запрещена.
- `harness/relocate-workspace.py --grant-admin` — однократное перемещение существующей рабочей среды в `/opt`, совместимая ссылка и **права администратора через sudo без пароля** для `orca` по прямому решению владельца. Также выдаётся доступ к Docker. Сценарий предназначен для нашей среды, не для запуска без проверки на другом сервере.
- `harness/install-harness.py` — развёртывание существующих навыков и правил Codex, регистрация проектов и служебные посредники. Исходные навыки, лицензии, закрытые данные и параметры входа остаются вне этого репозитория.
- `harness/professor-kb*` — работа с BookStack с сохранением контроля версий; `harness/professor-git-ssh*` — SSH для известных репозиториев без копирования закрытого ключа.
- `systemd/` и `bin/` — служба и запуск фиксированных версий. Подтверждённые проверки записаны в `validation.json`.

По решению владельца команды имеют полный доступ, включая `sudo -n`; ограничения изоляции команд отключены. Это настройка именно нашей установки. Исходные параметры чужих платформ сохраняются в metadata, но не становятся автоматически действующими хуками или внешними инструментами Codex.

`runtime/`, `.migration/`, данные входа, история и содержимое рабочих проектов исключены из Git. Ни одного закрытого навыка или документа BookStack этот репозиторий не содержит.
