# Платформа Orca и агенты Professor IT

Это действующее уточнение среды исполнения для перенесённых правил и навыков Harness. Содержательные правила проектов сохраняются. Инструкции ниже заменяют только обращения к отсутствующим инструментам DSH и старые расположения файлов.

## Файлы и права

Рабочая среда физически расположена в `/opt/professorit`. `/root/professor_ot` — совместимая ссылка для уже работающих служб. Для обычной работы используй пути `/opt/professorit`; старый путь можно преобразовать командой `professor-path ПУТЬ`. Проекты: `/opt/professorit/agent/projects`. В перенесённых копиях есть незавершённые изменения владельца: не очищай и не переключай их. Для разработки создавай отдельную рабочую копию Orca.

По прямому решению владельца пользователь `orca` имеет полный доступ через `sudo -n` и доступ к Docker. Изоляция команд отключена. Для операции, действительно требующей администратора, используй `sudo -n`. Наличие прав не означает задания менять работающие приложения, внешние публикации или рабочие данные: выполняй конкретное поручение и регламент соответствующего проекта.

## Знания

`professor-kb` в PATH — действующее средство доступа к BookStack. Оно сохраняет формат команд map/search/locate/read/facts/edit/create и проверки revision/SHA. Документы BookStack остаются единственной редактируемой документацией, а не локальным Markdown. `--output` и `--file` обрабатываются с правами вызывающего пользователя. Старый абсолютный путь `/root/professor_ot/bin/professor-kb` в перенесённых инструкциях означает `/opt/professorit/orca/bin/professor-kb`.

## Навыки и исполнители

Установленные навыки Professor IT расположены в `~/.agents/skills`; можно указать `$имя-навыка` или прочитать соответствующий SKILL.md. Инструмент DSH `skill` отдельно не существует.

Для совместной работы используй штатную Orca orchestration. Прочитай установленные `orca-cli` и `orchestration` и загрузи руководство версии через `orca-ide skills get`. `subagent`, `subagent_fork` и именованные команды ролей из старых инструкций не являются инструментами этой среды: создавай исполнителя Orca с явно указанным навыком, входами и ожидаемым результатом. Сохраняй ограничения команды из TEAM.md; не обходи их переименованием или вложенными запусками. Не подменяй требуемую работу исполнителя собственным выводом.

Используй реальные инструменты выбранного агента для чтения, изменения, поиска и запуска команд. Не выдумывай DSH `todo_write`, `job_output`, `run_in_background` или `workflow`. Состояние карточки меняй через `orca-ide worktree set --workspace-status`; согласование и отчёты исполнителей — через штатные задания, сообщения и решения Orca.

## Долгие работы

Для долгого бэкапа, сборки или деплоя сохрани ответственность за конечный результат, даже когда текущий ход закончился.

1. До запуска проверь активные операции и выбери адрес возврата в Orca. Сохрани ID операции, место журнала и критерий успеха. Для выпуска через CI/CD используй предусмотренный проектом конвейер.
2. Запускай конечную команду на сервере независимо от браузера и SSH владельца. Подходят существующий планировщик, CI или именованная сессия tmux. Подключай обработчик завершения при запуске. Обработчик сохраняет код выхода и результат под ID операции и сообщает координатору об успехе **и** об ошибке. Для внешнего CI жди итогового статуса конкретного пайплайна.
3. Для поручения исполнителю Orca координатор после подтверждённого старта заканчивает ход. Штатный worker_done возвращает итог, когда исполнитель завершил проверку. Если команда ушла в фон, исполнитель заранее организует отдельное событие её завершения. В контексте исполнителя с разрешённым адресом Run обработчик может отправить обычное сообщение через orca orchestration send. Сохраняй квитанцию доставки отдельно. Сообщения с кодом и ID достаточно; журналы и секреты остаются на сервере.
4. Пока команда работает, модель не проверяет статус по таймеру и не запускает агента-наблюдателя. После события координатор проверяет журнал и результат: например, читаемость архива или рабочую версию сервиса. При ошибке продолжает диагностику. При потере уведомления восстанавливает результат по ID, не запускает операцию повторно вслепую.
5. У tmux нет автоматической обратной связи с чатом. Если канал возврата для этого запуска не настроен, используй блокирующее ожидание завершения в одном вызове инструмента в пределах его тайм-аута либо сообщи об ограничении до запуска. Ручной вызов пользователя не должен быть штатным продолжением.

## Git и внешние инструменты

Репозиторий настроек Orca находится в GitHub `alphaserver777/orca` по прямому решению владельца; прежнее общее указание «все origin только GitLab» к нему не относится. Остальные проекты сохраняют свои origin и регламенты. Средство SSH для Git использует ключ администратора через проверяемый посредник, ключ в профиль агентов не копируется.

Навык не устанавливает и не подтверждает наличие внешнего инструмента. Если для видеомонтажа, Pronin, встроенной медиатеки DSH или иной функции нет действующего инструмента в текущем сеансе, сообщи конкретный пробел. Не объявляй наличие файла навыка проверкой работы всей интеграции.
